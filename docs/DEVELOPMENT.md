# PC Watt

轻量、本地优先的 Windows 10/11 桌面功耗与电费查看器。技术栈：C#、WPF、.NET 10、MVVM、SQLite。

**当前已接入真实硬件组件功率与自动整机估算。** CPU/GPU 优先读取设备功率；内存、硬盘、风扇等有瓦数接口时使用读数，否则采用明确标注的通用估算。不会把转速、温度或负载当成瓦数，不把组件之和标为整机实测。原有模拟记录单独保留。

已实现工程骨架、生命周期与设置、人民币电价历史、通知、真实组件采集、自动整机估算、电费优先的部件切换、日/月/年耗电图表（分色堆叠柱与总量折线）、温度/占用率、显示器会话状态和托盘悬浮读数。产品基线见 [PRODUCT-REQUIREMENTS](PRODUCT-REQUIREMENTS.md)，后续安排见 [ROADMAP](ROADMAP.md)，最新验证见 [图表与显示器状态验证](VALIDATION-CHART-DISPLAY.md)。

项目当前位于 `D:\工作间\PCWatt`。**双击根目录 [启动.cmd](../启动.cmd) 打开软件**；工程和当前状态见 [PROJECT.md](../PROJECT.md)。启动入口使用自身目录定位可运行预览，兼容中文和空格路径。

## 构建与运行

需要 Windows 和正式版 .NET 10 SDK。进入解决方案目录：

```powershell
dotnet restore PCWatt.sln --locked-mode
dotnet build PCWatt.sln
dotnet test PCWatt.sln
& .\src\PCWatt.App\bin\Debug\net10.0-windows\Launch.cmd
```

也可使用 Visual Studio 打开 `PCWatt.sln`。`global.json` 接受 .NET 10 正式版 feature band，当前验证使用 SDK 10.0.401。构建不需要管理员权限；WPF 与渲染测试需要 Windows，Core 和 Infrastructure 自身以 `net10.0` 为目标。

本机最新运行目录为 `artifacts/PCWatt-calm-chart-display-preview/`，发布包为 `artifacts/PCWatt-calm-chart-display-win-x64-framework-dependent.zip`。完整工程双击根目录 `启动.cmd`；独立解压包双击 `Launch.cmd`。需要 x64 .NET 10 Windows Desktop Runtime，保留整个目录（包括 launcher 子目录）。构建产物不纳入源码版本控制。正在运行旧窗口时，从托盘正常退出后重新打开即可使用新版。

启动入口使用已安装的 .NET 运行时加载 `PCWatt.App.dll`，程序主进程不附带控制台窗口。Windows PowerShell 仅作为短暂的启动辅助，不是常驻后台进程。该方式兼容本工作区生成 exe 继承低完整性标签的环境；直接双击受限 exe 会显示中文指引，尚未写入用户设置或数据库时即停止。

程序默认启用当前用户登录后自启动。首次运行将小型无窗口启动器正常部署到 `%LOCALAPPDATA%\PCWatt\Launcher`，主程序保留在 D 盘；HKCU Run 直接调用该启动器的 `--background`，不经过 cmd 或 PowerShell。辅助进程创建隐藏的 .NET 主进程后退出，不增加常驻进程。关闭自启动立即移除本程序注册项，不影响当前运行。移动主目录后正常运行一次即可更新目标路径。

**默认开启“启动时读取完整硬件”**：首次手动启动或登录自启动时，通过正常 Windows UAC 请求管理员授权，以便读取 CPU。已在运行时不重复请求；选择“否”仍继续普通权限记录可读硬件与明确标注的部件估算。设置中可独立关闭，下次启动生效。程序不绕过 UAC，不创建高权限计划任务、不安装驱动；授权后仍需要设备与现有接口支持。普通模式的“启用 CPU 读取”会请求授权，原进程保存数据并退出后，由新实例接手。

启动诊断仅写本地 `%LOCALAPPDATA%\PCWatt\logs\startup.log` 与 `launcher.log`，含时间、进程、完整性级别、启动目标及错误堆栈；超过 256 KiB 时轮换一份。没有找到用户此前报错的历史日志，不能断言原始错误原因；新入口已通过本机命令重放，实际再次登录仍需验收。

**关闭主窗口默认释放整个界面、留在托盘继续记录；点开托盘重新加载界面。** 完全退出请在托盘菜单选择“退出”；也可关闭“关闭主窗口后留在托盘”设置。重复运行会请求打开已有实例。

## 生命周期与持久化

每用户使用一个命名互斥量控制实例，通过仅允许当前用户访问的本地命名管道唤回窗口。用户级自启动仅操作 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下本程序的 `PC Watt` 项，不访问机器级启动项。

`SamplingCoordinator` 是应用拥有的唯一采样循环。窗口不再调用采集器；切换频率调整等待，不创建第二个循环。修改自启动或动效不会重置采样等待。暂停、退出和休眠会取消正在进行的可取消读取，并释放支持 `IAsyncDisposable` 或 `IDisposable` 的来源对象，恢复后按需创建新的来源。

默认数据路径：

```text
%LOCALAPPDATA%\PCWatt\simulation.db
%LOCALAPPDATA%\PCWatt\settings.json
```

每 30 秒或累计 6 帧触发一次事务批量写入；一帧包含多个独立传感器，目录信息与样本在同一事务保存。暂停与正常退出会保存待写数据。界面合并内存缓冲与已保存记录，刷新不会重复积分，也不会强制每个传感器各写一次数据库。

写入失败时保留整个批次供重试，达到缓冲上限会暂停新增采样。正常退出保存失败时保持进程和待写记录，明确提示重试退出。崩溃、强制终止或断电可能丢失尚未提交的缓冲数据；下次启动建立新记录边界，不补齐未完成区间。Windows 会话退出另有最长五秒的尽力保存，不保证强制终止情形下所有缓冲已提交。

SQLite 使用参数化 SQL、WAL 和不可变唯一键。当前 schema 5，可从 schema 1/2/3/4 在事务中升级，保留所有旧样本、电价及通知日期，保存传感器目录和整机估算属性。`simulation.db` 沿用旧文件名，其中真实硬件、整机估算和模拟历史按 Source 隔离。损坏文件和未知 schema 会报错并保留，不静默删库重建。

手动备份时先从托盘完全退出，再复制数据库及仍存在的 `-wal`/`-shm` 文件；仅关闭窗口不会停止写入。当前没有一键备份、恢复或清理历史界面。

## 时间积分与缺失规则

同一来源相邻有效样本的积分：

```text
E(kWh) = ((P1 + P2) / 2) × 实际间隔小时数 / 1000
```

1. 使用 `DateTimeOffset` 和实际时间差，存储 UTC ticks；按本地日期切分每日边界，兼顾夏令时的 23/25 小时日。
2. `(Source, UTC 时间戳)` 唯一且第一次写入生效。重复、重放或重启不重复累计；统计从原始数据重算。
3. 跨午夜的有效段在午夜处计算功率并裁切，相邻两日之和保持一致。当前日不使用未来样本。
4. 过长间隔、负数、空功率和不可用质量状态都保留为未知区间，不按零功率处理，不使用当前读数补算。
5. 第一个点之前和最后一个点之后不外推；只有一个点不产生耗电。真实零功率与未知功率不同。
6. 暂停、恢复、重启、休眠或时钟跳变后的第一条样本带记录边界，短暂停顿也不会被跨越积分。运行时系统时间回退期间不把新样本插入既有历史时间。
7. 新样本保存当时的 `MaximumIntervalSeconds`。有效阈值为基础阈值与三倍采样间隔的较大值：默认 30 秒采样对应 90 秒，1 分钟采样对应 180 秒。相邻段采用两端阈值较小者，频率变化不会放宽旧样本的规则。
8. schema 1 的旧样本没有间隔元数据，继续使用保留下来的基础阈值；频率开关不修改该基础值。`MaximumIntegrationGapSeconds` 为高级基础配置，范围 2–300 秒。
9. 覆盖率 = 有效积分时长 / 当地零点至统计结束的时长；缺失区间返回起止时间和原因，可在重启后从记录恢复。
10. 单次积分只接受一个来源，拒绝混合 CPU/GPU 等重叠测量流。整机账单分别积分所有整机方案历史，再拼接互不重叠的有效段；不同方案之间不连线，两套整机记录重叠的部分记为 `SourceConflict` 未知区间，不重复收费。组件和模拟历史不进入整机账单。

曲线使用受端点约束的视觉过渡；积分始终使用原始时间戳和功率进行梯形计算。`MockPowerSource` 保留供测试使用，生成 45–125 W 并带低可信度、模拟与估算标记；正式启动不再创建模拟源。

## 用户设置与人民币电价

设置使用带 `SchemaVersion: 2` 的 `settings.json` 原子保存，各开关独立，兼容版本 1。首次迁移优先读取原有 `appsettings.local.json`，否则读取程序目录 `appsettings.json`；存在用户设置后以其为准。已有的 5/10/30 秒选择会保留，旧 2 秒设置迁移为 5 秒；未保存采样频率时默认 30 秒。迁移不修改旧配置原件。

界面只提供人民币电价，中文显示“电价（元/度）”“预计电费（元）”。单价不预设；未填写电价时费用仍为未知，不影响记录。1 度电 = 1 kWh，默认不包含整户固定月费。

在设置中填写人民币每度电单价与本地生效日期，保存为新电价版本。每日期只有一个版本；首次配置可选择历史日期，已有历史后仅允许从今天或未来新增版本，同日重复或追溯改价会明确拒绝，保留原规则。当前不提供历史版本删除或覆盖编辑；可通过新的生效日期调整以后电价。

单价使用小数点，范围 0–1,000,000 元/度、最多 6 位小数；空值、负数、非数字、分组逗号、科学记数法、异常大值和过多小数会给出提示。功耗、电量和费用使用 decimal；按生效午夜裁切原始线性功率段并分别计费，最后按人民币“分”四舍五入，不使用显示舍入结果重新计算。未配置的区间保留未计价电量。

旧固定单价仅在电价历史为空时一次导入，生效日期为最早旧记录的本地日期，没有样本时为今天；之后设置文件中的旧单价字段不覆盖电价历史。内部保留原币种元数据以恢复旧记录，界面不提供其他币种，旧金额不会被冒充为人民币或自动换汇。首页电费始终对应整机有效记录，今日从本地零点开始，本月从本地月初开始，截至当前已记录时间；不是整月预测，也不是电力公司账单。部分记录未配置人民币电价时不把部分金额展示成完整费用。

## 启动通知与昨日报告

两个通知开关独立保存，默认关闭，下次启动生效；同时启用时合为一条。启动通知如实提示运行或暂停状态。昨日报告按本地日期，每自然日最多尝试一次；同日重复启动不重复报告，启动通知开关仍独立生效。设置中的报告详情可随时刷新，查看覆盖率、缺失、模拟/估算说明、生效单价和版本。

昨日可靠报告门槛为**覆盖率至少 80%，且有效覆盖至少 1 小时**。不足时不展示具体耗电和电费，只说明数据不足；可靠报告也仅统计实际覆盖时段，不把缺失时段补齐。正式启动的昨日报告与设置中的报告详情均统计整机，不随所选组件变化，标明整机估算及覆盖范围，排除旧模拟记录。

通知通过现有系统托盘交给 Windows，不增加常驻进程。数据库在提交通知前保存尝试日期，以避免异常退出后的重复提示；若提交后系统抑制通知、发送失败或进程中断，当天不会重试昨日报告。系统托盘不可用时不占用报告日期。是否实际展示受 Windows 通知设置影响，通知失败不影响采样与保存。


View/ViewModel 不直接访问 SQLite 或硬件。组合根负责装配；Core 不引用 WPF、SQLite 或 Windows API。接口包括 `IPowerSource`、`IEnergyRepository`、`IEnergyCalculator`、`ICostCalculator`、`IClock`、`ISamplingController`、`IPowerDashboardService`、`ITariffRepository`、`IPriceSchedule`、`INotificationHistory` 与 `IUserNotificationSink`。分时电价仅保留策略接口。

`PowerSample` 包含时间戳、可空 decimal 功率、来源、可信度、估算标记、质量状态和可选间隔规则。`PowerChannel` 记录硬件名称、组件类型、统计范围和可用性。`IMultiPowerSource` 提供统一时间戳的多传感器帧，仍由一个调度循环驱动；`IChannelDashboardService` 隔离来源选择与图表读取，`IWholePcBillingService` 独立提供整机账单。`TemperatureSample`/`ITemperatureProvider` 与 `UtilizationSample`/`IUtilizationProvider` 只提供当前温度和占用；复用原硬件帧，不增加调度器、硬件会话或 SQLite 记录，也不进入功率估算、电量积分和收费。ViewModel 不接触硬件或数据库。

CPU 占用使用 Windows [GetSystemTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes) 的两次计数差，内核时间包含空闲时间，因此先扣除空闲差值；首次采样需等待建立基线，暂停恢复后重新开始。超过 64 个逻辑处理器时当前实现不把单处理器组当作全机占用，返回未知。物理内存通过 [GlobalMemoryStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex) 的总量/可用量计算，两者均不要求管理员权限。显卡只采用 LibreHardwareMonitor 的 GPU Core 负载，不把显存、总线、功率百分比作为核心占用，也不与核显相加；口径可能与任务管理器最忙引擎不同。

采集 CPU/GPU、CPU 暴露的 DRAM 功率及磁盘瓦数接口；可访问 PawnIO 时启用主板风扇识别。磁盘功率接口不可访问时通过 Windows WMI 识别物理盘，仅用型号/设备标识区分磁盘，不把活动率当作瓦数。不启用额外内存 SPD 或 USB 控制器组。应用不调用风扇调速、超频、电压设置或驱动安装功能。CPU 读取前检查现有 PawnIO 接口，避免不可读时的零值被当成测量。单个附加设备初始化失败不移除已有 CPU/GPU；暂停/退出释放库对象。

本机普通权限可读 RTX 5060 Ti 功率及 AMD 核显功率域；管理员启动后已读到 Ryzen 7 9700X 的 CPU 总功率。ZHITAI Ti600 1TB、内存、主板和两路风扇没有可用瓦数，分别标为估算。不同设备支持不同；组件遥测可信度为中，估算为低，均不能代替外部功率计。SoC/Core/Package 可能重叠，切换查看不改变整机聚合规则。

## CPU 与整机功耗

CPU 只显示封装总功率，不叠加 Core、SoC、PPT；多插槽仅在所有独立封装可读时合并。没有总功率时保持未知。本机普通权限读取 PawnIO 返回 Win32 5，管理员身份可读；默认启动会请求 Windows 授权，也可保留普通模式。自动识别独显总功率；已知核显不与 CPU 封装重复计入。不明确或不可用的必要 GPU 功率会令整机保持未知。

当前没有外部功率计实测。默认自动估算：

```text
整机估算 W =（CPU 封装 W + 独显 W + 内存/硬盘/风扇/主板 W）/ 0.90
```

内存优先采用有效 DRAM 瓦数，磁盘优先采用每块物理盘的有效瓦数；没有接口时使用通用常数：系统内存合计 8 W、每块已识别硬盘 3 W、每路已识别风扇 2 W、主板其余部分 12 W。无法识别磁盘或风扇数量时，分别采用整类 3 W/4 W 的通用假设。风扇转速仅帮助识别连接，不换算功率，未使用的零转速接口不视为风扇。这些常数和 90% 电源效率均不是本机校准结果；项目名称、详情、样本与持久化均携带估算标记，不能据此判断设备精确能耗。

本机内存目前采用上述固定 8 W 通用估算，界面明确说明“非内存实时实测”；不能由此认定所有内存实际功耗恒定或始终很低。区间耗电也取决于有效记录时长，柱高变化不等于功率一定变化。内存占用率仍为独立 Windows 实读，不参与瓦数换算。

需要自行校准时展开“高级：手动校准整机估算”，可替换其余部件合计功率与效率。该合计替代自动小计，避免重复加入。点击“恢复自动估算”即可撤销手动方案。CPU/必要独显读数无效、过期、模拟或范围不安全时整机保持未知，不补零。

估算不含显示器，带低可信度和估算标记。自动方案根据稳定的设备/来源和规则生成 ID，重启不重复建立方案；设备或实测/估算来源改变时使用新 ID。手动保存也创建新方案，不用新假设重算旧样本。当前功率使用当前方案；整机账单和整机周期图包含范围内全部方案的非重叠有效历史，不桥接方案切换的缺口。外部功率计尚未接入。

CPU 温度优先采用 Tdie、Tctl/Tdie 或 Package，部分设备仅提供 Tctl 时使用该读数并在悬停中说明来源；不把 CCD/SoC 混作封装温度。显卡优先采用 GPU Core/GPU，不以 Hot Spot 或显存温度替代。多插槽 CPU 显示有效封装温度最高值。只显示当前读数，没有温度历史、告警或风扇控制。本机普通权限实读 RTX 5060 Ti 核心约 31°C；本轮 CPU 温度的管理员实机读数尚未验收，不保证所有设备可读。

图表上方增加显示器状态：亮屏、熄屏、已调暗或未知；悬停查看型号和能力说明。本机普通权限已实读 G24H2Classics 的当前亮屏状态。采用 Windows `GUID_SESSION_DISPLAY_STATUS` 的原生事件回调，注册后获取初始值，没有轮询、常驻隐藏窗口或新硬件驱动；主窗口释放后仍可接收，退出时注销。熄屏状态会停止前台装饰动效。
