# 硬件分色与总量折线验证

日期：2026-10-25。Windows 11 x64，.NET SDK 10.0.401。

## 确认行为

- 日、月、年周期柱顶叠加深墨青总量折线和小圆点，完全没有有效记录的分组不连线，真实零值仍能连接。折线仅表示分组已记录电量，不参与积分或收费，不补齐未知时间。
- 整机柱按 CPU 墨青、显卡蓝、内存紫、硬盘棕橙、其他灰绿堆叠；其他合并主板、风扇、手动其余部件参数及估计电源损耗。图例只显示实际出现的分类，悬停显示各部分电量与估算属性。部件图保留单色柱并同样叠加总量折线。
- 使用原时间戳对应的组件功率和可验证的方案拆分；自动方案 ID 必须重建匹配，按原规则重新算出的整机瓦数必须与已保存瓦数一致。已退役传感器的空记录不参与重建，CPU/核显重叠域不额外相加。
- 仅对原整机有效且无方案重叠的区间积分各部分，保留跨小时/日/月裁切规则；所有颜色部分之和等于原柱总量。CPU/显卡采用原组件读数，内存/硬盘沿用原估算属性，其他含估计损耗，整体仍为整机估算，非墙插实测。
- 旧手动方案参数已丢失、组件端点缺失或原瓦数不匹配时，整段记为灰色“未拆分”；当前仍保存的手动方案可核对拆分。不按当前占用率、固定百分比或当前硬件比例回填历史。没有数据库迁移或原样本改写。

## 自动化与渲染

Debug 与 Release 的 `dotnet build PCWatt.sln --no-restore`、`dotnet test PCWatt.sln --no-build --no-restore`（Release 加 `-c Release`）均成功：各 **238 通过、0 失败、0 跳过**，构建零警告零错误；锁定依赖还原与 win-x64 framework-dependent 发布通过。

新增 8 项测试覆盖自动拆分守恒/核显排除、端点缺失、总量不匹配、当前手动方案范围及旧方案灰色、跨小时 SQLite 恢复、方案重叠排除、退役空传感器排除，以及折线缺失断开/真实零值连接。结果：`artifacts/test-results/stacked-chart-debug.trx`、`stacked-chart-release.trx`。

三种周期的默认与最小尺寸实际 XAML 渲染图为 `artifacts/ui/stacked-chart-{day,month,year}-fixture.png` 和对应 `-minimum-fixture.png`，测试检查整机范围、五类分色和完整图表可见。布局样本的组成是明确设置的测试数据，带水印，不是生产拆分算法，也不进入用户数据库。原生 Windows 悬浮提示、多 DPI 和实时交互尚未单独实机验收。
