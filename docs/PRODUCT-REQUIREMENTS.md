# PC Watt — 产品需求补充与后续开发规范

需求基线始于 2026-10-24，依据用户后续确认更新至 2026-10-25。以下是产品验收目标，不代表当前代码已经具备全部功能。当前采用中文人民币计费，真实硬件和自动估算优先接入，首页仅保留主要部件分类与单条对应曲线；范围与验收计划见 [ROADMAP.md](ROADMAP.md)。

用户已要求改善界面、增加动态并继续分阶段开发。各阶段实际实现和待办以 ROADMAP 与验证记录为准。

## 项目定位

PC Watt 是一个轻量、开源、本地优先的 Windows 10/11 电脑功耗与电费统计工具。

技术栈：C#、WPF、.NET 10、MVVM、SQLite。

产品原则：

- 轻量、低后台开销、单进程运行。
- 默认开机自启动，用户可以关闭。
- 关闭主窗口后默认进入系统托盘，继续后台记录。
- 电费由用户配置，不预设固定地区电价。
- 明确区分硬件实测值、组件功耗、整机估算值和未知数据。
- 不上传用户数据，不要求账号，不强制联网。
- 不添加与核心用途无关的功能。

## 一、启动与后台生命周期

1. 默认启用 Windows 用户登录后自动启动。
2. 设置页提供独立的自启动开关。
3. 使用当前用户级启动机制，配置启动项本身不要求管理员权限。完整硬件模式默认通过 Windows UAC 请求管理员授权，用户可独立关闭或取消；取消后继续普通权限记录，不绕过授权。
4. 关闭自启动后立即移除对应启动配置，但不强制退出当前运行的程序。
5. 关闭主窗口默认隐藏到系统托盘，后台继续采样。
6. 托盘菜单至少提供：打开主窗口、显示最近功耗、暂停/恢复记录、设置、退出。
   托盘图标支持鼠标悬浮查看整机总功耗、CPU 温度和显卡温度；估算明确标记，不随应用中所选组件改变，不新增后台采样循环。
7. 完全退出时停止采样、持久化待写数据、释放硬件资源并关闭数据库。
8. 防止重复启动多个实例。
9. 后台记录提供精细（5 秒）、细（10 秒）、一般（30 秒）、省电（1 分钟）四种模式，默认一般；保留已有有效档位。
10. 采样器必须只有一个有效的调度循环，切换档位不得创建重复定时器。
11. 开机自启动、启动通知、昨日用电报告、关闭窗口行为、采样频率分别保存为独立设置。

## 二、通知系统

提供两个独立的通知设置：

- 启动通知：提示 PC Watt 已启动并正在后台记录。
- 昨日用电报告：每天首次启动时汇报昨天的耗电量和估算电费。

如果两项均启用，应合并为一条通知，避免重复打扰。

昨日报告规则：

- 按本地日期判断，每个自然日最多发送一次。
- 昨日必须有足够的有效记录才能展示具体耗电量。
- 无数据或数据不足时，明确提示无法生成可靠报告。
- 昨日数据完整度、估算属性和电费口径必须可查看。
- 保存通知日期，避免程序在同一天多次启动时重复发送。
- 用户关闭通知后仍然正常记录。
- 系统通知不可用时，不影响采样和数据保存。

## 三、功耗与电费计算

1. 区分 CPU、GPU、其他组件、整机估算功率和外部功率计实测值。
2. 组件功率之和不得直接标记为整机实测功率。
3. 每个样本记录时间戳、数据来源、估算标记、可信度和质量状态。
4. 采用时间积分累计 kWh，处理重复时间戳、异常间隔、暂停、休眠和跨午夜分日。
5. 长时间缺失的区间不得自动补零或使用当前功率补算。
6. 统计结果应包含数据覆盖率与未知区间信息。
7. 采样频率改变后不能重复累计历史样本。
8. 电价、货币和电量计算逻辑必须与硬件采集层分离。
9. 每个硬件传感器独立记录与计费；切换分类或设备后，其功率、耗电、费用、覆盖率和曲线采用同一来源。查看选择不改变后台采集范围。
10. Core、SoC、Package 可能重叠，不能直接求和。真实采集不回退为模拟；CPU 接口不可读时显示未知，不安装驱动。
11. CPU 显示封装汇总项，不把核心/SoC/PPT 重复计入。默认启动请求正常管理员授权；重复实例不重复请求，普通模式可一键请求授权并正常交接采样。
12. 界面区分整机和硬件功耗。整机默认自动识别来源并采用明确标记的通用估算；必要 CPU/显卡数据缺失时保持未知，不补零。高级参数按需展开，可恢复自动方案，改规则不重算旧记录。
13. 内存、风扇、硬盘等优先获取有效瓦数，没有时采用低可信度的通用估算；标明具体来源与假设。转速、温度、容量和负载不能冒充实测瓦数，已计入封装或显卡板卡的项目不得重复累计。
14. 首页面向初学者，仅提供整机、CPU、显卡、内存、硬盘五项分类与对应曲线。风扇、主板等小部件计入整机估算，不单列首页选项；同类多个设备按短名称切换，技术来源与质量信息收起，估算标记仍明确显示。

## 四、人民币电价设置

第一版支持：

- 用户设置人民币每度电单价，界面显示“电价（元/度）”。
- 只提供人民币，不显示其他币种选项；电费显示为“元”，使用中文说明。
- 设置电价生效日期。
- 保存电价历史，允许后续查看或调整。
- 修改当前电价不得意外覆盖历史账单的计价规则。
- 默认不将整户固定月费计入电脑电费。
- 输入必须验证：电价不能为负数，空值和异常数值需要给出清晰提示。
- 金额使用适当的十进制定点计算方式，避免直接用浮点数进行最终货币舍入。
- 第一版先实现统一电价。分时电价只预留接口，不必立即实现。

## 五、统计界面

首页以费用为主：今日整机电费最突出，其次为本月已记录整机电费；显示已记录电量、覆盖率与估算标记。只保留整机、CPU、显卡、内存、硬盘五项，切换只影响功率与曲线，不改变电费范围。缺失时段不推算，不把部分计价金额展示成完整账单。

日/月/年分段控件同时联动下方图表：今日按小时、本月按天、今年按月统计已记录耗电量（度/kWh）；同步横轴、累计值、覆盖率和悬停详情。整机图包含全部整机方案，部件图跟随所选来源；当前功率卡保留实时 W 和最近十分钟平均/峰值，不把历史耗电柱当作当前功率。

周期柱顶叠加总量折线，完全缺失处分段。整机柱按 CPU、显卡、内存、硬盘及其他分色堆叠，图例与悬停显示各部分消耗；其他包含主板、风扇及估计电源损耗。拆分必须依据可核对的原记录，颜色之和与总量一致；依据不足的旧记录以“未拆分”保留，不用当前比例回填历史。

直接显示当前 CPU 和显卡温度，优先选择封装/核心读数，不要求用户选传感器；选择显卡时跟随当前设备。温度复用原采样循环，不可读、暂停或过期时明确提示，不估算温度。当前实现只含实时温度读数。

应用内直接显示 CPU、显卡、内存占用百分比；CPU 与内存固定系统范围，显卡跟随所选设备。提供简洁占用条，读数来源与统计口径可查看，缺失不补零；占用率不作为功率或电费推算依据。

提供小时、天、周、月、年五种视图。

| 视图 | 默认范围 | 默认粒度 |
| --- | --- | --- |
| 小时 | 最近 60 分钟 | 分钟 |
| 天 | 今天 | 小时 |
| 周 | 最近 7 天 | 天 |
| 月 | 当前自然月 | 天 |
| 年 | 当前自然年 | 月 |

所有视图至少展示：

- 累计耗电量 kWh。
- 按相应电价计算的估算电费。
- 数据覆盖率。
- 实测与估算的说明。
- 数据缺失提示。

支持选择历史日期。统计范围使用清晰一致的本地时间规则。当前尚未完成的日期、月份和年份只展示实际已记录的数据。

交互补充：采用简洁的柔和功耗曲线、悬停读数和轻量动效，不以密集数据表格或长传感器列表作为主界面。

## 六、报告与数据管理

1. 提供一键复制用电报告。
2. 报告包括时间范围、耗电量、人民币电价、估算电费（元）、数据覆盖率及估算说明。
3. 支持导出 CSV 和 JSON。
4. 支持备份与恢复。
5. 提供清除历史记录功能，必须二次确认。
6. 清除历史默认保留用户设置与电价配置，除非用户明确选择全部重置。
7. 所有数据默认只存储在本地。

## 七、设置页

至少包含：

- 开机自启动开关。
- 启动通知开关。
- 昨日用电报告开关。
- 关闭窗口后进入托盘开关。
- 后台采样频率选择。
- 人民币电价（元/度）与生效日期设置。
- 导出数据、备份恢复、清除历史。
- 暂停/恢复记录。
- 关于、许可证和隐私说明。

设置应简洁，常用选项直接展示，高级选项按需展开。

## 八、资源与异常恢复

- 单进程、单采样循环。
- 默认每 30 秒采样，支持 5 秒、10 秒、30 秒、1 分钟四档。
- 数据批量持久化，避免每个传感器每次读取都写数据库。
- 窗口隐藏后停止不必要的 UI 更新。
- 退出或暂停时释放硬件对象。
- 传感器初始化失败不能导致整个软件崩溃。
- 单个传感器异常不应阻断其他传感器。
- 程序异常退出后，下次启动能够恢复历史数据。
- 未完成的采样区间应标记为不完整，不得自动补齐。
- 采样任务可取消，切换设置不会泄漏定时器或后台任务。
